# Comando gw:update.balance

El comando `gw:update.balance` es uno de los más importantes del sistema, encargado de actualizar los saldos de clientes y cuentas por cobrar basándose en las facturas firmadas electrónicamente.

## Información General

- **Comando**: `gw:update.balance`
- **Clase**: `PlanetaDelEste\GW\Console\UpdateBalance`
- **Propósito**: Actualización masiva de saldos contables
- **Optimizado para**: Grandes volúmenes de datos

## Sintaxis

```bash
php artisan gw:update.balance [company] [opciones]
```

### Argumentos

| Argumento | Tipo | Descripción |
|-----------|------|-------------|
| `company` | int (opcional) | ID de la empresa a procesar |

### Opciones

| Opción | Valor por Defecto | Descripción |
|--------|-------------------|-------------|
| `--id` | - | ID específico de factura a procesar |
| `--customer` | - | ID de cliente específico para filtrar |
| `--chunk-size` | 500 | Cantidad de registros por lote |
| `--memory-limit` | - | Límite de memoria para el proceso |

## Funcionamiento

### 1. Algoritmo de Procesamiento

El comando utiliza una estrategia híbrida de **cursor + chunk** para optimizar memoria y velocidad:

```php
// Cursor para lazy loading (eficiente en memoria)
$query->cursor()
    // Chunk para procesamiento en lotes (eficiente en velocidad)
    ->chunk($chunkSize)
    ->each(function ($chunk) {
        foreach ($chunk as $invoice) {
            $this->updateInvoiceBalance($invoice);
        }

        // Liberación de memoria entre lotes
        gc_collect_cycles();
    });
```

### 2. Filtros Aplicados

El comando procesa únicamente facturas que cumplan:

- ✅ **Firmadas electrónicamente** (`sign_at IS NOT NULL`)
- ✅ **No rechazadas** (`status != 'rejected'`)
- ✅ **Con tipo de movimiento** (`invoice_movement_type_id IS NOT NULL`)
- ✅ **Ordenadas por fecha** (`ORDER BY sign_at ASC`)

### 3. Proceso de Actualización

Para cada factura procesada:

1. **Limpia saldos existentes** (si es procesamiento completo)
2. **Calcula nuevos saldos** usando `BalanceHelper`
3. **Actualiza registros** de balance
4. **Registra actividad** en logs

## Ejemplos de Uso

### Actualización Completa
```bash
# Procesar todas las empresas
php artisan gw:update.balance

# Mostrar progreso detallado
php artisan gw:update.balance -v
```

### Empresa Específica
```bash
# Procesar empresa ID 1
php artisan gw:update.balance 1

# Con configuración personalizada
php artisan gw:update.balance 1 --chunk-size=200 --memory-limit=1G
```

### Filtros Específicos
```bash
# Cliente específico
php artisan gw:update.balance --customer=100

# Factura específica (útil para debugging)
php artisan gw:update.balance --id=12345

# Combinando filtros
php artisan gw:update.balance 1 --customer=100 --chunk-size=50
```

### Configuración para Recursos Limitados
```bash
# Configuración conservadora
php artisan gw:update.balance --chunk-size=25 --memory-limit=128M

# Para servidores con pocos recursos
php artisan gw:update.balance --chunk-size=10 --memory-limit=64M
```

## Optimizaciones de Performance

### Configuración de Memoria
```bash
# Configuraciones recomendadas por entorno

# Desarrollo local
--memory-limit=512M

# Servidor pequeño
--memory-limit=256M --chunk-size=100

# Servidor grande
--memory-limit=2G --chunk-size=1000

# Producción crítica
--memory-limit=4G --chunk-size=2000
```

### Tamaño de Lote Óptimo

| Volumen de Facturas | Chunk Size Recomendado | Memoria Sugerida |
|---------------------|------------------------|------------------|
| < 10,000 | 500 (default) | 512M |
| 10,000 - 50,000 | 300-500 | 1G |
| 50,000 - 100,000 | 200-300 | 1-2G |
| > 100,000 | 100-200 | 2G+ |

### Garbage Collection
```php
// Activado automáticamente en el comando
gc_enable();

// Ejecutado después de cada lote
gc_collect_cycles();

// Pausa mínima para no saturar
usleep(1000); // 1ms
```

## Manejo de Errores

### Errores Comunes

#### Empresa No Encontrada
```
Error: Company not found
```
**Solución**: Verificar que el ID de empresa existe.

#### Memoria Insuficiente
```
Fatal error: Allowed memory size exhausted
```
**Solución**: Aumentar `--memory-limit` o reducir `--chunk-size`.

#### Factura Inválida
```
Error processing invoice ID 12345: Invalid movement type
```
**Solución**: El comando continúa con las siguientes facturas.

### Recuperación de Errores
```bash
# Ver último error detallado
tail -f storage/logs/laravel.log | grep -i error

# Reprocesar desde punto específico
php artisan gw:update.balance --id=12345

# Modo debugging
php artisan gw:update.balance 1 --customer=100 -vvv
```

## Programación Automática

### En Kernel.php
```php
protected function schedule(Schedule $schedule)
{
    // Actualización diaria a las 2 AM
    $schedule->command('gw:update.balance')
        ->dailyAt('02:00')
        ->withoutOverlapping(120) // Timeout 2 horas
        ->appendOutputTo(storage_path('logs/balance-update.log'))
        ->emailOutputOnFailure('admin@empresa.com');

    // Actualización conservadora para producción
    $schedule->command('gw:update.balance --chunk-size=100 --memory-limit=512M')
        ->daily()
        ->environments(['production']);
}
```


## Consideraciones Especiales

<Warning>
**Bloqueo de Transacciones**: El comando puede bloquear tablas durante la ejecución. Evitar ejecutar en horarios de alta actividad.
</Warning>

<Info>
**Orden de Procesamiento**: Las facturas se procesan cronológicamente por fecha de firma para mantener consistencia contable.
</Info>

<Tip>
**Optimización**: Para bases de datos muy grandes, considera ejecutar por empresa individual en paralelo.
</Tip>

### Verificación Post-Ejecución

